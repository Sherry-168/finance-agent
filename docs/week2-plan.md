## 2. 具体任务拆解

### 👑 史雅萱（后端与工程化 / 队长）

**核心接口落地**

- 完成 `/records/parse`（对接 Dify）、`/records`（入库）、`/stats`（图表）、`/alerts`（主动提醒）接口。
- 配置 CORS 跨域。
- 完成 Docker 打包，确保一键跑通。

**全模态支持**

- 新增 `/api/v1/voice` 接口：接收前端传来的音频文件（需引入 `python-multipart`）。
- 拿到音频后，调用李语琛提供的 ASR 函数转换成文字，再走后续解析入库流程。

### 🧠 李语琛（AI 核心）

**核心任务**

- 交付稳定的 `agent.py`（封装 Dify 调用）。

**全模态与加分项支撑（重点发力）**

- **语音转文字（ASR）**：使用阿里云百炼（免费额度）或智谱的语音 API，写一个 `speech_to_text(audio_file)` 函数交给后端，将用户说的「打车32」转为文本。
- **多模态多笔拆单**：完善 Dify 的多模态能力，支持长截图返回 JSON 数组。
- **Agent 拟人化**：在 Dify System Prompt 中写死多轮追问逻辑、越界拒绝（拒绝套现网贷），并根据后端传来的超支数据生成「人味儿」提醒文案。

### 💾 蔡适伶（数据与规则逻辑）

**核心任务**

- 提供所有增删改查的 DAO 层函数，以及图表统计 SQL。

**主动提醒核心（重点）**

- **预算警戒算法**：扫描本月各类别支出，计算消耗比例（>80% 橙色警告，>100% 红色超支）。
- **异常巡检算法**：对比单笔支出与历史均值，找出「畸形消费」。
- **定时任务**：将生成的警告写入 `notifications` 数据库表，供后端接口读取。

### 🎨 林丹苗（前端与可视化）

**核心任务**

- 对接真实接口，完成草稿卡片确认入库，Plotly 画饼图和折线图。

**全模态与 UI 美化（重点发力）**

- **语音输入 UI**：在聊天框旁边加一个 `gr.Audio(source="microphone")` 组件（录音按钮）。用户录完音后，将音频文件 POST 给后端的 `/voice` 接口。
- **全局主动提醒横幅**：调用 `/alerts` 接口，在页面顶部显示醒目的红 / 橙色警告横幅（支持已读关闭）。
- **UI 质感升级**：隐藏 Gradio 默认样式，做聊天气泡 + 卡片界面；加一个「一键演示」按钮。

### 🛡️ 江为（测试与文档交付）

**核心任务**

- 端到端测试抓 Bug。

**全模态与提醒专项测试**

- **语音测试**：实测在不同麦克风、有环境噪音下的语音识别准确率。
- **造「触发警告」数据**：生成能把预算撑爆的测试数据，验证提醒横幅。
- **答辩物料**：制作多模态演示录屏（语音说一句话 → 系统弹出警告 → 生成图表），完善 README。

## 3. 🚨 队长防翻车指南（必须在群里强调）

1. **Docker 体积警报**：严禁本地部署语音识别模型！语音转文字全部走云端 API，保证 Docker 镜像依然轻量。
2. **麦克风权限**：前端同学测试语音时，记得允许浏览器获取麦克风权限。如果评委的电脑没麦克风，**必须保留原有的文本输入框作为降级方案**。
3. **分清主次**：语音输入是「锦上添花」，如果录音模块联调太卡壳，就先切回文本输入，**绝对不能影响核心的「记账 → 查账」闭环**。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| ASR 云端 API 配额 / 网络不稳定 | 语音演示失败 | 保留文本输入作为降级；提前录制演示视频 |
| Dify 输出格式与后端契约不一致 | 解析失败、入库中断 | 后端做数组 / 对象双兼容适配层 |
| 麦克风权限与设备差异 | 评委环境无法演示 | 文本输入框始终可用；演示用预录音频 |
| 多人并行改动同一文件 | 合并冲突 | 每人一分支、走 PR；接口契约先改 `docs/api.md` |
| Docker 镜像膨胀 | 构建慢、评审跑不动 | 依赖只装必要项，ASR 走云端，构建后清理缓存 |
