## 1. 项目说明（Project Description）

* **做了什么**：面向个人日常消费记录与分析的智能记账助手，用户可通过自然语言或上传账单截图，快速完成记账。
* **面向场景**：把「录入一笔账要点击五六次」压成「一句话 / 一张小票」，把「查一个数要翻筛选器」压成「随口一问」，解决传统手动记账繁琐、分类困难的问题。
* **设计原则**：**LLM 只做理解和生成，所有算账、统计、预算判断一律由 Python + SQL 完成。** 模型输出结构化槽位，金额换算、时间区间、SUM/COUNT、预算比较全部走代码，杜绝模型算错账。

## 2. 技术栈与架构简述

* **前端**：Gradio 6 + 自定义 CSS + ECharts（五区界面：记账对话 / 明细 / 统计 / 预算 / 演示）
* **后端**：Python 3.11+ · FastAPI · Uvicorn（`/api/v1`，统一响应 `{code, message, data}`）
* **数据**：SQLite（标准库 sqlite3，金额以「分」整数存储，避免浮点误差）
* **AI 核心**：Dify 工作流 + DeepSeek 多模态视觉大模型
* **部署**：Docker · docker-compose（一条命令启动后端 + 前端）

## 3. AI 核心模块说明

本项目核心 AI 驱动层采用 **Dify 工作流** 搭建，接入 **DeepSeek 多模态视觉大模型**。

### 核心功能

* **自然语言输入**：如“打车花了25块”，AI 自动提取结构化数据。
* **多模态图片识别**：上传购物小票、外卖订单、淘宝账单截图，AI 直接读取内容。
* **多笔账单拆分**：长截图包含多笔消费时，拆分为 JSON 数组输出。
* **结构化输出（JSON）**：严格 Prompt 约束，强制标准 JSON 格式，方便后端解析入库。

### 数据输出示例（多笔图片识别）

```json
[

  { "amount": 159, "category": "购物", "description": "RK R75Pro客制化无线机械键盘", "date": "11-10" }
```

## 5. 快速启动（Quick Start）

### Docker 方式（推荐）

```bash
cp .env.example .env        # Windows 用户请手动复制并重命名
docker compose up --build
```

启动后访问：

* **前端界面**：http://localhost:7860/
* **后端健康检查**：http://localhost:8000/api/v1/health
* **后端接口文档**：http://localhost:8000/docs

> **数据持久化**：`docker-compose.yml` 用目录挂载（宿主 `./data` ⇄ 容器 `/app/data`），数据库为 `/app/data/finance.db`，容器重建不丢数据。`docker compose down -v` 不会删除数据；清空请删宿主 `data/finance.db`，或在「演示数据」页点「清空演示数据」（`POST /demo/reset`）。
> 端口：后端 `8000`、前端 `7860`，均由 compose 显式声明。
>
> 已实测（Windows 11 + Docker Desktop 29.9.3）：`docker compose up --build` 后 backend `healthy`、前端 7860 返回 200、`/api/v1/stats/summary` 返回真实数据；容器重建后流水与预算仍在。pip 走清华镜像，国内构建约 45 分钟。

### 本地开发（不使用 Docker）

```bash
pip install -r requirements.txt
pip install -r frontend/requirements.txt
cp .env.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload     # 终端 1
cd frontend && python app.py                                  # 终端 2
```

## 8. 功能清单与验证方式（60 笔数据版）

> ⚠️ 本节全部数字已按**新的 60 笔演示数据**重算，与原产物的 15 条版本不同。合并演示数据前请勿照抄旧值。

### 8.1 准备演示数据

进入「演示数据」Tab，点「灌入演示数据」（`POST /demo/load`）：

* 预期提示 **60 条流水 / 2 个月份**（2026-10-01 ~ 11-15）✅
* 自动布置 4 条当月预算（总额 4000、餐饮 1200、交通 500、娱乐 100）——⚠️ 请队长确认 `/demo/load` 的预算布置是否随数据更新
* 重复点击不重复灌入（幂等）

### 8.2 功能 1：自然语言记账 + 入库

「记账」Tab 输入 `昨天打车 32 块`（`POST /records/parse`）：

* 预期 `fields.amount = 32`、`category = 交通`、`occurred_at` 为昨天；
* 点「确认入库」，刷新「明细」能看到这条；
* 输入 `花了点钱` 不瞎猜，返回 `clarify_question = 请输入金额`。

> 这 20 条解析用例（正常 / 缺金额 / 缺时间 / 模糊时间 / 金额单位 / 无意义）见 `tests/demo_parse_cases.json`，含「3k」「三十二块」「上周五」等边界。

### 8.3 功能 2：自动分类与统计

「统计」Tab 三类视图（`GET /stats/summary`、`/stats/by-category`、`/stats/trend`）。以 60 笔数据为准，**2026-11（本月）** 预期：

| 指标 | 预期值 |
|---|---|
| 总额 | **¥6081.03** |
| 笔数 | **18 笔** |
| 日均 | ¥552.82（按有数据的 11 天；以实现口径为准） |
| 占比最高 | **购物 ¥3470.44（57%）** ← 含 11-08 大额 ¥2999 |
| 其次 | 居住 ¥1850.00（30%） |

> 原产物此处为「总额 ¥2410.40 / 9 笔 / 居住占 83%」，那是 15 条数据的旧值，已作废。

### 8.4 功能 3：自然语言查账（60 笔版）

示例与预期回答（**本月 = 2026-11，上月 = 2026-10**）：

| 提问 | 预期 `answer_text` |
|---|---|
| 我上个月吃饭花了多少？ | `10 月，「餐饮」共支出 ¥946.58，共 20 笔。` |
| 我上个月娱乐花了多少？ | `10 月，「娱乐」共支出 ¥1190.38，共 7 笔。` ← **娱乐超支演示点** |
| 这个月哪类花得最多？ | `11 月，花得最多的是「购物」，共 ¥3470.44（57%），5 笔。` ← 大额消费所致 |
| 最近 7 天一共花了多少钱 | 按数据基准日 11-15 算 → ¥422.04（5 笔） |
| 最近 30 天支出趋势 | 逐日 `table`，最高一天为 **2026-11-08（¥3116.18）** ← 大额消费日 |

回答数字全部由 SQL 聚合；`slots` 回显解析出的时间区间与类别，便于核对。

### 8.5 功能 4：预算与超支提醒

「预算」Tab 设娱乐类 100 元，**本月（11 月）娱乐已用 ¥110.99 → 111%，`status = over` 进度条变红** ✅（与原产物 113% 接近，演示点保留）。

* 设总额 4000 元 → 已用 ¥6081.03 = 152%，同样 `over`（⚠️ 若想演示 `normal` 状态，需把总额预算调到 8000 以上）
* 预警阈值 80% = `warning`，判断在后端完成

> 娱乐超支的**大数字**在 10 月（¥1190）；11 月只有两笔西西弗咖啡 ¥110.99，刚好卡在 100 元预算上方。两个口径都能演示超支，讲解时说清“本月 vs 上月”。

| `tests/demo_parse_cases.json` | 20 条解析用例 | 文本解析测试 |

### 9.2 两个刻意埋设的演示点

1. **娱乐超支（查账演示）**：10 月底 5 笔娱乐共 ¥1054，10 月娱乐合计 ¥1190.38；11 月娱乐仅 ¥110.99。问「上个月娱乐花了多少」命中。
2. **大额消费（趋势 / 预算演示）**：11-08 京东商城 ¥2999，当日合计 ¥3116.18，为近 30 天最高。问「最近 30 天趋势」「这个月哪类花得最多」命中。

### 9.3 ⚠️ 三个待队长确认的口径

1. **`confirmed` 必须置 1**：查账链路只取已确认记录（`db-design.md` §6）。`/demo/load` 若按默认草稿态 0 入库，演示数据查出来全是 0。
2. **金额换算**：DB 列是 `amount_cents`（整数分），CSV 是元，入库须走 `yuan_to_cents()`，否则统计缩小 100 倍。完整校验值：CSV 总额 ¥10508.31 = **1,050,831 分**。
3. **类别词典**：娱乐演示点依赖 `config/categories.json` 识别 K歌之王 / 万达电影 / 密室大逃脱 / Steam / M-Club 酒吧；新 8 类无「通讯」，话费 ¥39 会落「其他」。

### 9.4 时间基准

本数据是**测试样本**，按固定区间 2026-10-01 ~ 11-15 构造，用于演示功能，**不随现实时间变化、也不对标答辩当天日期**。演示时：

* 「本月 / 上月」按数据内的年月解析（本月 = 11 月、上月 = 10 月），与真实日期无关；
* 「最近 N 天」等相对时间按数据基准日算，预期值见 §8.4；
* 想让数字稳定可复现，优先用**绝对时间问句**（如「2026 年 10 月娱乐花了多少」），避免依赖运行日。
